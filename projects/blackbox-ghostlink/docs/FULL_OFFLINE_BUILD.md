# BLACKBOX + GHOSTLINK — complete owned build and field-data pipeline

Version: **0.4.0**. Source of truth: `thotsl4yer69/survival-companion`, branch `main`, directory `projects/blackbox-ghostlink`.

The GitHub **source repository** contains all of our authored application code, radio/ESP32 adapters, 3D CAD source and STL meshes, tests, installers, the offline-asset builder, geographic renderer, complete versioned download catalog and verification system. It intentionally excludes private data and third-party gigabyte binaries. The **field-data pack** is a distinct binary deliverable generated by a reproducible CI job and also reproducible locally. Both are part of this project.

## One connected workstation command to build an actual offline data pack

The connected Linux workstation needs Python 3.11+, `osmium-tool` and Pillow (`python3 -m pip install 'Pillow>=11,<13'`). Plan on at least 7 GB free during build and several gigabytes for data transfer and staging, particularly because both JetPack 5 and JetPack 6 offline Ollama runtimes are included. The exact amount depends on current upstream files and locally rendered map coverage; a GitHub runner must have enough free disk.

```bash
cd projects/blackbox-ghostlink
python3 offline/prepare.py plan --profile bendigo
python3 offline/prepare.py assemble --profile bendigo --dir /mnt/blackbox_assets --output /mnt/BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar
python3 offline/prepare.py inspect --output /mnt/BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar
```

`assemble` does **actual downloads** (not placeholders), builds a PNG raster MBTiles map from the Victoria OpenStreetMap extract via `osmium`, records real SHA-256 hashes of every source and derivative and creates one verified, portable TAR. If the internet is unavailable, download is interrupted or any data is missing, the process fails; it never labels an unprovisioned pack ready.

The pack contains:

- Official Qwen2.5 1.5B Q4_K_M **GGUF** inference weights (~1.1 GB) and upstream Apache-2.0 licence file for local Ollama import.
- Kiwix Wikipedia English Top Mini **ZIM** snapshot (September 2026; hundreds of MB), readable through `kiwix-serve` without internet.
- Geofabrik **Victoria OSM PBF** source extract (hundreds of MB), with OpenStreetMap ODbL / contributor attribution.
- **Bendigo region raster MBTiles** generated locally from the actual OSM data, usable in BLACKBOX's raster map viewer. It uses basic OSM styling, roads and water/land features; no elevation contours, guaranteed routing, terrain hazards or certified navigation.
- Pinned official ARM64 Ollama **JetPack 5 and JetPack 6** runtime archives plus the official Kiwix Tools 3.8.2 AArch64 archive. The correct Ollama build depends on the exact Jetson OS; **do not launch both**. Ollama v0.34.0 release SHA-256 values are pinned to those published by its maintainers.
- A JSON manifest with source URLs, real byte counts, SHA-256s, derivative-map metadata and explicit readiness flags. The TAR checksum is written alongside.

**Important:** the OSM source PBF is not itself a rendered map. The renderer requires `osmium` and Pillow *during preparation*. Runtime BLACKBOX needs neither. Model weights are not executable inference on their own: a compatible offline runtime must already be installed on the target.

## Transfer and activate with NO internet

The release may be split into numbered `.tar.part-01`, `.tar.part-02`, etc because GitHub imposes a 2 GiB per-asset limit. Download all parts and the corresponding `.tar.sha256`, then use our included safe, hash-verified reassembler (which rejects missing or out-of-order parts):

```bash
python3 offline/rehydrate.py \
  --part BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar.part-01 \
  --part BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar.part-02 \
  --output BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar \
  --sha256 BLACKBOX_FIELD_DATA_bendigo_v0.4.0.tar.sha256 \
  --extract-to /srv/blackbox-offline
```

The example shows two parts. Supply **exactly** the numbered files actually published; if there is a single `.tar`, supply it as one `--part`. The tool hashes the reconstructed TAR before extracting and rejects unsafe filenames, symbolic links and existing populated destination folders.

Alternatively transfer a pre-built single TAR from a connected workstation, verify the accompanying checksum, and use `offline/rehydrate.py` to unpack it.

On the target:

```bash
mkdir -p /srv/blackbox-offline
# Only extract packs you generated and verified; see the security note below.
# Skip this extraction command if you used the verified offline/rehydrate.py above.
cd /opt/blackbox
python3 offline/activate.py --assets /srv/blackbox-offline/assets
python3 offline/activate.py --assets /srv/blackbox-offline/assets --import-model
```

`--import-model` calls the locally installed Ollama command to register `blackbox-qwen2.5:1.5b` using the downloaded GGUF. It verifies the source pack first. Start a locally installed `kiwix-serve` with the ZIM file to browse Wikipedia. Set:

```text
BLACKBOX_OLLAMA_MODEL=blackbox-qwen2.5:1.5b
BLACKBOX_MBTILES=/srv/blackbox-offline/assets/maps/bendigo-raster.mbtiles
```

in `/etc/blackbox/blackbox.env` on a dedicated BLACKBOX host, then restart BLACKBOX after reviewing privileges. No port forwards or cloud accounts required during operations. JetPack-specific Ollama and Kiwix AArch64 archives **are present in a successfully assembled field pack**; they are intentionally absent from the source ZIP. Extract the correct runtime for your actual JetPack version and verify all native shared-library dependencies before relying on it. `--import-model` still requires a running Ollama service; the pack cannot prove it will run without on-device tests. GPU inference on an Orin is hardware-dependent and is not yet benchmarked.

⚠️ Never unconditionally extract unknown TAR files as root. Verify the `.sha256` and unpack only project-produced archives in a dedicated location. This builder uses safe relative entries and no executable files in the data pack.

## Operating without the host

The database and field notes are stored in SQLite with private-file permissions. Export a self-contained printable field report from BLACKBOX, and maintain a second copy on independent storage. The field pack contains reference data and an LLM model, **not your private inventory database or personal files**. Back up operational records separately.

## External dependencies and why we didn't fork them

We own the integration and field-build pipeline. We do *not* fork and rebrand upstream repositories without necessity: a fork won't magically include model weights, map extracts or licence permissions, and it creates unsupported duplicate maintenance work.

| Dependency | Official upstream | Function | State |
|---|---|---|---|
| Qwen2.5 GGUF | https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF | Optional local LLM weights | Fetched and hashed by pack builder; not embedded in Git |
| Kiwix ZIM | https://download.kiwix.org/zim/wikipedia/ | Real offline encyclopedia | Fetched and hashed by pack builder |
| Geofabrik / OSM | https://download.geofabrik.de/australia-oceania/australia/victoria.html | Real map source | Fetched, rendered and hashed |
| Osmium Tool | https://osmcode.org/osmium-tool/ | Pre-build PBF extraction and GeoJSONseq export | Required only on connected build machine |
| Pillow | https://pillow.readthedocs.io/ | Pre-build PNG raster rendering | Required only on build machine |
| Ollama | https://ollama.com/download/linux | Pinned JetPack 5/6 runtime archives in field pack | Select matching release; verify hardware-specific behaviour |
| Kiwix Tools | https://github.com/kiwix/kiwix-tools | AArch64 native tools archive in field pack | Extract and verify on target |
| Meshtastic Python | https://python.meshtastic.org/ | Optional physical LoRa gateway | Untested RF until two real nodes connect |

Upstream URLs may change, mirrors can move, and a fresh online build may download new content under a `latest` source path. Every successful pack includes its real SHA-256 digests, which verify it thereafter; this does *not* claim independent signature verification of original upstream content. Keep the manifest and exact TAR checksum for provenance. Preserve upstream licences, attribution and distribution terms.

## What is honestly complete

**Complete as source:** runnable offline software, generated printable CAD meshes, ESP32 firmware *source*, actual data provisioning and raster generation pipelines, extensive offline integration tests, GitHub Actions tests, archived releases and installation documentation.

**Incomplete as a deployed device:** Orin hardware installation; any radio transmission; GPS receiver; calibrated hazard sensors; batteries/solar switching; ESP32 flashing; production-grade map validation; actual Kiwix and local LLM run under blackout conditions. Each must pass the hardware gates before being called operational. The existing Orin installation is not modified by this repository push.
